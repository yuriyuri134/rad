# OpenLab Bench 架构观察报告（P1 实践实证）

本报告基于本次真实 Optiland 0.6.3 光学设计全过程（9+ 轮次、隔离 Python 3.12 环境、独立纯 NumPy 物理复算）的一手观察，对照 `B0 v0.2` 假设逐项检验。

---

## 一、实践过程能力边界观察

### 1. AI 能够可靠自主完成的工作
- 根据真实玻璃折射率与 Abbe 数解析推导单透镜（Coddington 弯曲）与双胶合（消色差光焦度分配）初始处方；
- 阅读已安装软件源码核对 API 签名，避免凭记忆写错参数（本次在运行前及运行中排查出 `optiland_bridge.py` 6 处隐患与 `edge_thickness` 数组返回值 Bug）；
- 构造自动化实验流水线、批量运行多轮对比实验与材料分支（`N-F2` vs `SF5` vs `N-SF11`）；
- 编写零依赖的独立物理复算程序，与专业软件逐字段交叉核验。

### 2. 必须有外部验证与防呆机制兜底的环节
- **优化器静默假成功**：`B1` 中 `scipy.optimize.least_squares` 返回 `success=True`，实际上 `nfev=1`、目标函数一步未动（因为 Optiland 吞掉了操作数抛出的异构数组异常）。**任何工作台不能只存优化器返回的 `success` 布尔值，必须记录 `nfev`、`initialSumSquared -> finalSumSquared` 与前后处方实际变化量**；
- **隐藏对焦作弊风险**：若系统未显式锁定与记录 `fixedBflMm` 及 `focusRule`，求解器默认的 `image_solve()` 会悄悄重新对焦；而对比 `B2` 与 `C1`（仅差 `0.372 mm` 离焦）时，`0° d` 线光斑从 `11.90 μm` 剧变至 `39.83 μm`；
- **软件默认行为陷阱**：`Material("F2")` 静默解析到 `hikari` 目录、`GeometricMTF` 在特定离焦下产生 `30 lp/mm` 零点伪分辨、切光用 `i<=0` 而非 `NaN` 表达——这些都无法靠通用 JSON Schema 察觉，必须由物理审查员与领域自检用例暴露。

## 二、对照 `B0 v0.2` 的实证检验

### 1. 在实践中确实成立、发挥关键作用的设计
- **执行账本不可覆盖、保留失败与反例（`ExecutionRecord` 只追加）**：`A3`（强迫单透镜消色差失败）与 `B1`（首次 `N-F2` 优化停滞）提供了最有价值的物理与软件诊断证据，保留而非覆盖是完全正确的；
- **执行与决策分离（三图基本切分）**：`B1` 停滞后派生 `B1_retry`，`B2` 精调出 `B2_refined`，`B2/B3` 作为材料分支并行比较——这些属于“研究分支/重跑决策”，不应回写污染既有轮次的原始输入输出；
- **明确区分不同物理域与参考系**：几何光线追迹、几何 MTF、Airy 衍射参考盘、质心参考点（`chief_ray` vs `centroid`）在实践中极易混淆，必须在产物信封/元数据中强制声明 `domain` 与 `focusRule`；
- **独立物理复算（验证者与执行者解耦）**：Agent 2 独立程序直接交叉核对了 `EFL`、`BFL`、`F-C` 色差、`edge_thickness` 与 `3D` 点列 RMS，确保结果可信。

### 2. 暴露出的现行架构缺口（`B0 v0.2` 未充分覆盖）
1. **缺少“实验迭代谱系 / 诊断原因”轻量链接**：`B1 -> B1_retry` 是因为边缘厚度 Bug 调整厚度重跑，`B2 -> C1` 是针对同一处方切换对焦基准的重评。`B0 v0.2` 虽提到 `retry`/`rerun`，但未在核心记录中明确 `parentRoundId` / `relationType (diagnostic_retry | weight_refinement | focus_sensitivity | material_branch)`；
2. **多维条件矩阵产物表达不足**：真实光学评价不是单一 `rmsSpotRadiusUm` 标量，而是 `3 视场 × 3 波长 × 多参考系` 矩阵加 `GeometricMTF` 曲线加边缘厚度/遮拦统计；
3. **运行环境发现与可配 Python 解释器缺失**：`runner.ts` 硬编码 `'python3'`，导致即使系统存在隔离 `Python 3.12 + Optiland` 环境也无法在不改代码的情况下被工作台发现和使用；
4. **优化器执行过程（`nfev`、残差变化、边界命中、SciPy 警告）未纳入标准执行摘要**：导致类似 `B1` 的“表面成功实则停滞”容易蒙混过关。

### 3. 在实践中显得过重或暂不需要的抽象
1. **`ResearchObject` 独立多版本化**：整个 P1 过程中研究目标始终只有一个（`100 mm F/4` 几何光学基准对比），真正频繁分叉和演化的是分支处方、实验轮次与评价规则；
2. **两层嵌套 Execution DAG（外部 `ExecutionRecord` 图 + 内部 `steps[]` DAG）**：P1 每轮实验天然对应“一次配置 -> 一次求解/优化 -> 一次多条件评价 -> 一次独立复算”，扁平的 `ExecutionRecord` 链已足够清晰；
3. **探索期强契约准入**：如果研究初期每写一个临时脚本（如 `verify_physics.py` 或临时消色差求解器）都要先补全 12 项档案和 9 项强类型端口，会大幅拉长从想法到验证的反馈周期。
