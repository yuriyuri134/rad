# M1 科研执行

## 运行边界

开发服务绑定 `127.0.0.1`。浏览器调用只接受本机同源请求。组件以服务账户权限运行，信任边界包括本机用户、项目源码、组件目录和 Python 环境。审批确认特定版本的源码 SHA-256，Python 本地模块通过组件档案中的 `module` 依赖 `local:相对路径.py` 声明并在审批时固定。执行器核对后把入口和已固定依赖写到临时目录。请审阅入口及其声明的依赖，尤其是能读写其他文件、导入依赖或调用子进程的代码。

## 科研更正

- S2 四个采样视场的多色 RMS 为 2.476–3.221 μm，550 nm FFTPSF Strehl 为 0.77730–0.86549。0.25° 和 0.42° 低于 0.80。分支对比依据 [S2 原始处方与逐视场指标](../experiments/p2_flagship/runs/branch_S2.json) 投影。
- Stage 4 的原始报告给出两组 40 次模拟。在最大 RMS ≤ 7.5 μm 条件下，两者通过率均为 100%。仅 BFL 的 P50/P95 为 3.781/5.289 μm，M2 垫片加 BFL 的 P50/P95 为 2.070/3.086 μm。源文件为 `experiments/p2_flagship/runs/stage4_tolerancing.json`，SHA-256 为 `955cd06883ba40a57e8001c086013746eaf73e1e2abe0246a092ab2a62318b0c`。
- E6 的 88.2% 衡量 DAO 和 SEP 的代理匹配。历史 Stage 3 的 65.4% 以模拟注入真值为分母。E6 的 DAO 独有检出留待逐星评估。更正适用于工作台展示，原始 E6 数据仍可复核。
- Stage 3 模拟将同一天球位置与通量投影到每份处方的像面。探测器只累加边界内的 PSF 像素。超出探测器的模型能量按比例损失。评价有效星要求模型质心位于探测器内，且保留至少 90% 的归一化有限光斑能量。评价报告应同时给出有效视场保持率和有效星的检出率。

## 文件执行协议

组件版本的 artifactContract 声明 openlab-files/v1、命名输入输出、媒体类型、Schema ID，可选 JSON Schema、参数约束和 Python 包版本。批准后，可由研究工作台或 /api/research/executions 执行。CLI 从 stdin 读取 inputs、parameters、outputDir 和 manifestPath。inputs 的每个端口包含产物 ID、哈希、媒体类型、Schema ID 和一个本次运行的本地副本路径。组件写入 outputDir，再向 manifestPath 保存一个形如 {"outputs":{"report":"report.json"}} 的小型清单。stdout 和 stderr 用于日志。

一次执行的全部输出只有在发布完成记录后才可见。子进程启动前，已核验的入口和依赖写入 Stage A1 CAS，并将组件版本与这次执行关联。修改已执行的版本需要派生新版本。服务启动时会为可核验的 M1 历史执行补齐冻结关联。若同一版本的历史记录与当前实现冲突，原记录留存，继续运行需要新版本。

已结束的记录保留自己的端口、参数和运行环境快照。输入必须通过媒体类型、Schema ID、适用的 JSON Schema 和哈希校验。配方续跑会核对组件版本、入口与依赖哈希、契约、实传参数、运行环境和输入产物后再复用。中断时以已发布的执行记录为依据恢复。

同一个数据目录由一个工作台服务进程负责。科研执行归档位于 workspace/workbench/research，可通过 OPENLAB_WORKSPACE_DIR 移到持久化数据目录。

## 从工作台继续研究

1. 启动服务后访问 http://127.0.0.1:3000。在研究工作台选 WF-RC-1000，选择 S1–S4 与视场。默认的 S3 0.60° 会实算一帧。选择全部可执行 16 帧。
2. 在运行记录中选一个步骤，打开日志、输入、输出和环境。已结束的配方可以从指定步骤重跑，保留现有的兼容上游产物。也可以展开独立执行，选评分组件、原来的真值与星表，调整匹配半径后启动。
3. 在产物与对比查看合并的三方法结果，点开对应的逐星真值、检测表与匹配明细。FITS 查看器可检查像素与文件头。组件库展示所选版本的契约和真实使用记录。架构地图展示发布后的输入、生成执行与下游消费者。
4. 其他实验可以通过 /api/research/import-json 导入有来源的 JSON 输入，通过 /api/components/create 登记带 artifactContract 的组件，再审阅和批准相应版本。/api/research/recipes 接受由既有产物 ID 或前序步骤端口组成的有序配方。

## WF-RC 实算复核

运行 node --import tsx scripts/verify_wf_rc_m1.ts <新数据目录>。脚本需要科学 Python 环境，依赖缺失、步骤失败或复算不一致均会失败。加 --smoke 只运行 S3 0.60°。完整测试包含 132 个步骤、16 帧曝光及 48 份评价，并重跑一个评分步骤验证上游复用。verification.json 记录两个运行 ID 和逐帧结果。组件的代码与环境指纹在各步骤记录中。

下表来自 S1–S4、四个视场、同一曝光三种方法、4 px 一对一匹配的完整运行。本次使用 Python 3.12.13、Optiland 0.6.3、Astropy 8.0.3、Photutils 3.1.1、SEP 1.4.1。448 颗共同星场注入星中有 438 颗满足有效评价条件，样本的视场保持率为 97.8%。

| 提取方法 | 匹配 / 有效星 | 漏检 | 误检 | 完备率 | 精确率 |
| --- | ---: | ---: | ---: | ---: | ---: |
| DAO 3.0 px | 299 / 438 | 139 | 9 | 68.3% | 97.1% |
| DAO 1.5 px | 398 / 438 | 40 | 15 | 90.9% | 96.4% |
| SEP | 438 / 438 | 0 | 0 | 100% | 100% |

[完整 M1 实算摘要](evidence/wf-rc-m1-verification.json) 记录了 16 帧逐帧统计、48 份评价的汇总、真实执行参数和环境，以及共同星场、原处方、FITS、真值、星表和评价文件的 SHA-256。摘要从原始 M1 批次及其单步重跑记录提取。

S3 的 0.60° 帧有 26/28 颗有效星，DAO 两种核宽分别匹配 14/26 和 23/26，SEP 匹配 26/26。三种提取用了同一份曝光，位置 RMS 依次为 0.0644、0.0939 和 0.0598 px。较小的 DAO 核宽在本批次提高了完备率，增加了误检。星场疏密、通量分布、噪声模型及半径都是本批模拟条件。SEP 的结果适用于该验证样本。文件中的位置误差为探测器像素残差。

## 实施边界

步骤使用有序配方与命名端口，组件注册和审批采用已有档案。Node 文件组件可用内建模块及声明后随版本核验的本地模块。Python 运行环境由操作者提供。归档记录已安装的包，工作台会核对组件声明的固定版本。进程按本机用户权限执行，文件暂存与内容校验提供可追溯性。回退时可用 M1 前的应用版本读取旧账本，M1 的运行目录可单独保全。
